再说开发环境。文字版里有一步一步的操作，我这里只讲为什么要这么做。

第一，我们会给这个学习项目单独建一个 Python 虚拟环境。你可以把它理解成项目专用的依赖仓库，跟 Java 项目里每个工程有自己的依赖配置是一个道理。好处是装坏了可以删掉重来，不影响电脑上的其他东西。

第二，调用大模型需要一个 API key。这个 key 就相当于密码，花的是真金白银。所以我们约定：key 只放在环境变量里，不写进代码，不提交到 git。这个习惯在公司里尤其重要，你肯定不希望某天在代码仓库里看到自己的 key 被别人拿去用了。

第三，我们的代码使用 OpenAI 官方的 Python 开发包，但不代表只能用 OpenAI。现在很多模型服务商都提供所谓的“OpenAI 兼容接口”，你只要改一下服务地址、key 和模型名，同一份代码就能切换到别的服务商。这样做的好处是不被某一家绑定，以后公司如果有自己的模型网关，也能很快接上。

还有一条安全提醒：练习阶段只用公开的或者脱敏的数据。真实客户的姓名、电话、地址，不要发给外部的模型服务。公司允不允许用外部接口，最好提前问清楚。

好，进入今天的正题：大模型是怎么工作的。

我先给你一个最朴素的比喻：手机输入法的联想功能。你打了“订单已”三个字，输入法会提示“发货”。大模型做的事情本质上一样：给定前面的文字，预测接下来最可能出现的片段。只不过它在海量文本上训练过，联想能力强了无数倍。它回答你的问题，其实是把答案一小段一小段地“续写”出来：先算出下一个片段，接到末尾，再根据新的全文算下一个，如此循环，直到它判断该结束了。

这里的“片段”，就是我们常说的 token。token 不是字，也不是词，而是模型内部切分文本的最小单位。英文里，常见单词一般就是一个 token，比较长或者生僻的词会被拆成几段。中文没有固定的换算比例，一个常见汉字可能是一个 token，也可能被拆成好几个，这取决于具体模型的分词方式。另外，数字、标点、JSON 里的大括号和引号，也都要占 token。

所以有一个很重要的习惯：不要拍脑袋估算 token，要看接口返回的用量。每次调用模型，返回结果里都会告诉你这次输入用了多少 token、输出用了多少 token。今天晚上的练习，就是让你亲手对比中文、英文和一段订单 JSON 各自占多少 token。你很可能会发现，一个订单详情的 JSON，比你想象的要“贵”。

为什么说 token 是费用单位？因为几乎所有服务商都是按 token 收费的，输入和输出分开计价，而且通常输出的单价更高。所以，你发给模型的每一个字、它回给你的每一个字，都在花钱。

接下来是第二个核心概念：上下文窗口。上下文窗口，是模型一次能“看到”的全部内容的上限。注意，这里的“全部内容”包括：你写的系统提示、全部的历史对话、你附带的资料，还有模型这次要生成的回答。输入加输出，合起来不能超过这个上限。

我喜欢把它比作一张工作台。台面多大，决定了你能同时摊开多少资料。但是台面摊得越满，就一定干得越好吗？不是的。Anthropic 的官方文档里提到一个现象：随着上下文变长，模型的准确度和回忆能力会下降，他们把这个现象叫做 context rot，可以翻译成“上下文腐化”。说白了，资料越多，重点越容易被淹没。所以好的做法是只放这一次任务真正需要的内容。

这里还有一个特别容易混淆的点：上下文窗口和最大输出长度不是一回事。最大输出长度只限制这一次模型最多能写多少字；而上下文窗口是输入加输出的总容量。窗口很大，不代表模型会写很长；最大输出长度设得太小，回答就会被拦腰截断。这个我们明天会专门做实验。

最后一个要点：模型知道的东西，来自它的训练数据。上下文窗口则是它的“工作记忆”。亚米的订单、商品、售后政策，训练数据里是没有的。你不把这些信息放进上下文，模型就看不到，看不到就只能猜。怎么在合适的时候把合适的资料放进去，是后面第三阶段 RAG 要解决的问题。

我们拿亚米的客服场景来串一下。假设你在做一个客服助手，每次调用模型时，上下文里可能有这几样东西：一段系统提示，告诉它你是谁、要遵守什么规则；几段相关的售后政策；最近几轮的聊天记录；这位用户的订单信息；最后，还要给模型的回答预留空间。做上下文预算，就是把这几项都管住，别让任何一项失控。比如订单信息，不要把整个订单对象原封不动地扔进去，只保留状态、物流、金额这些回答问题需要的字段。这样既省钱、又更快，模型也更不容易答偏，还顺便减少了把不必要的个人信息发出去的风险。

好，我们来回顾一下今天的内容。第一，大模型的工作方式是逐个 token 往后续写，本质是一个非常强大的“下一个片段预测器”。第二，token 是模型处理文本的最小单位，中英文没有固定换算，要以接口返回的用量为准；token 既决定容量，也决定费用。第三，上下文窗口是输入加输出的总容量，是模型的工作记忆，资料放得多不等于答得好，这叫上下文腐化。第四，最大输出长度只管输出，别和窗口搞混。

留三个问题给你想一想。第一个：如果有人跟你说，“这个模型窗口有一百万 token，那我们把整个商品库都塞进去就行了”，你会怎么回应他？第二个：为什么订单 JSON 要先裁剪字段再交给模型？你能说出至少两个理由吗？第三个：试着用三句话，向一个不懂技术的同事解释，为什么一个“只会预测下一个词”的模型，却能回答问题？
